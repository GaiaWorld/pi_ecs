# 帧间调度与阶段入口数据流

实现根：本 workspace。宿主入口在 [App](../../crates/pi_ecs_app/src/app.rs)，端口在 [System](../../crates/pi_ecs_schedule/src/system.rs)，数据流在 [SystemFlow](../../crates/pi_ecs_schedule/src/inter_frame.rs)，阶段入口在 [Stage](../../crates/pi_ecs_schedule/src/stage.rs)。每个壳由同名 \_inner.rs 接线；新增运行路径仍是实现桩。

本轮验证：cargo check --locked --workspace --lib、cargo test --locked -p pi_ecs_schedule -p pi_ecs_app --features rc、RC 工作区 Dylint 和 git diff --check 均通过。回归覆盖普通阶段和真实 Schedule 的故障出口；新版整批回调及帧间执行仍待实现与验收。

## App 与队列

App 的帧间图和调度，以及调度下的阶段，通过受限配置视图追加配置。视图不交出底层对象的可变引用；入口图按值安装被拒绝时，原图随错误返回。

App、Schedule、Stage 只接管无既有登记责任的调度、阶段和未初始化 System；拒绝时 InstallError 交还原值。配置视图不开放注销；App 的注销入口使用其自有 World，独立 Schedule 的注销入口显式接收所属 World。

App 接管 World 前检查组装状态、外部订阅与查询登记以及活命令接收者，拒绝时交还原 World；保留的发送端不阻止接管。构建期 WorldConfig 仅提供登记与初始资源配置能力；冻结由 App::finish 统一完成。根初始化遇生产者变化时钟耗尽时，组合回滚仍在 Running 下执行；期间若生产者清偿又遇结构版本耗尽，也不截断后续 Reader 注销。退出登记作用域后停止并优先报告最初的时钟耗尽。已验证 App 接管与真实 World 根登记；尚未从 Schedule 注入生产者时钟耗尽。

首次队列核验只接受同一 Some(claim)，失败不取消息且保留清偿责任；Ready 后资格缺失、变更或探针出错属于运行故障。根 Running 的追踪维护时钟耗尽由 World 标停并保留原诊断，独立 Idle 维护仍保留原门禁语义。

- RC 单线程宿主持有 App，由 App 独占一个 World。空闲时可立即派发拥有型输入；也可通过 App 投递现有类型化命令队列。帧推中的应用系统可发起异步请求，完成回调只交付拥有型消息、不借 World、不重入帧推；在帧间由宿主驱动处理。
- 现有 CommandHub 仍持队列；绑定的帧间入口只有单位输入，通过普通 CommandReceiver 参数消费。按命令类型设「最高、高、中、低、最低」，默认「中」。App 在就绪队列间选择优先级，同级按绑定顺序，队列内按原有顺序。不再提供另外一套 InterFrameCommands。
- 每次启动前用宿主提供的当前时间、帧推期限和让行余量判断；已到或快到则原样保留消息。运行结果区分已跑一轮、无就绪、为帧推让行。已开始的轮次同步收束，不抢占；宿主仍显式发起帧推。

## 普通 System 的端口

- 普通函数调用不变，默认单位输入、无输出。带端口的函数经普通 SystemBuilder 和参数会话运行，输出是拥有型值，释放参数后才交付；None 表示不触发后继，Vec 等批次不隐式拆分。一批到期项只启动一次目标 System。
- 注册结束后在同一图内按非单位负载类型自动推边：唯一生产者可连接多个只读消费者，或一个拥有消费者。多生产者竞争、多个拥有者、读借用与拥有混合、触发环或不可满足的访问顺序均报错。普通帧阶段主体和其他图不参与跨图匹配。宿主立即入口的拥有型句柄可 Clone，指向同一实例而不延长其寿命；实例编号由图分配。
- 帧间按入口预编译，访问边排序但不激活；路由只看本轮实际通知。普通参数准备失败只阻断依赖其输出的后继，独立已就绪支链继续，结束报首错。World 停止或调度协议故障优先报告原始诊断，未交付项随轮释放。帧间一轮一次销毁屏障，新 Removed 可触发第二段，第二段新归零留待下一次收束。

## 应用模拟时间与定时回调

- 模拟 tick 和定时器由应用拥有并推进，不使用 ChangeTick 定时。定时消息由应用送入既有队列，消费系统轮到自己时读取；要求同轮可见时，把派发安排在消费前，例如「预计算 → 计算」。框架不用感知到期判据。
- 定时回调由目标阶段的入口图承接。应用登记一个单位入口轮询器，用普通系统参数读取模拟时钟和定时器；它只取本次已到期的值，返回 None 或一份非空批次。目标 System 用拥有或只读批次输入启动，在其自身参数作用域内重新借用 World；之后才执行该阶段普通系统。没有全局帧前定时回调，也不需要动态目标派发。
- 显式阶段序列可多次进入同一阶段并复用实例。每次入口重新轮询，已取出的到期项不重放；同一次入口新增的定时项不扩展已经取走的批次。重复阶段不会隐式推进应用模拟 tick。阶段入口与主体使用同一父 Schedule 根会话。

## 验收

- 默认普通函数仍走原 Stage 路径；应用轮询器和批次目标可经普通 SystemBuilder 组合真实 ResMut 及只读批次端口。
- 阶段入口 None 不运行回调；多个到期值触发一次并在主体前可见。重复进入同一阶段不重放旧值，应用未推进时钟时 ECS 不推进；不同阶段相同负载不串线。
- 帧推中产生的异步完成消息留待帧间；让行不消费，下一帧间可继续。就绪优先级默认中、更新生效、同级可确定，且不改变队列内顺序。队列声明和实际 Receiver 归属不一致时拒绝。
- 混合通知/输出环、类型歧义及过期句柄拒绝；普通失败不取消独立支链。屏障停机时原始错误胜过根通用错误；部分初始化仍清偿成功登记，注销正常诊断不跳过其他项。

验收分工：从 App/Schedule 验证让行不消费、阶段重复与普通主体前可见、停机根出口保留原错及部分登记清偿；芯单测覆盖触发/访问边分离、屏障第二段继续传播实际通知与输出、队列资格编号与误领拒绝、同级选择。取参前的类型拒绝须验证不调用参数 begin/fetch/finish。

普通阶段已发布计划的无效槽由真实 Schedule::run 回归覆盖：复用损坏计划时在派发前标停，保留原诊断，不运行同阶段系统或后续阶段。缺少必需资源仍走可重试的参数准备拒绝。

接缝约束：消费系统只拿 `CommandRead<'_, C>`，不能替换长期 Receiver；图登记只接受未构建的 SystemBuilder。组图、Stage 门禁和取参前校验共读构建时冻结的端口。阶段安装拒绝须归还原图；计划冲突只使图失败，普通阶段和数据流执行遇 tick／会话协议故障才标停 World。验收须覆盖真实 Schedule 主体故障的停机及原错传递，并区分普通准备拒绝。
